# 需求文件：手冊管理後台系統

## 簡介

手冊管理後台系統是一個基於 Laravel-Admin 的系統，用於管理多語言技術手冊和階層式菜單結構。該系統支持創建和組織手冊，包括樹狀導航菜單、頁面信息和跨多種語言的國際化內容。

## 術語表

- **Manual（手冊）**: 在單個手冊記錄下組織的相關文檔頁面集合
- **Manual_Menu（手冊菜單）**: 使用 ClosureTable 進行樹狀關係的階層式菜單結構
- **Manual_Page_Info（手冊頁面信息）**: 手冊頁面的元數據，包括標題和關鍵詞
- **Manual_Page_Content（手冊頁面內容）**: 特定語言的頁面實際內容
- **ClosureTable（閉包表）**: 用於高效存儲階層式樹狀結構的數據庫模式
- **I18N（國際化）**: 支持多種語言
- **URL_Slug（URL 別名）**: 手冊的 URL 友好標識符（例如："user-guide"、"api-docs"）
- **Click_Action（點擊動作）**: 點擊菜單項時觸發的動作（例如："navigate"、"expand"）
- **Lang（語言代碼）**: 語言代碼（例如："en"、"zh-TW"、"ja"）
- **Translatable（可翻譯）**: 使用 spatie/laravel-translatable 套件管理的多語言字段，存儲為 JSON 格式

## 需求

### 需求 1：創建和管理手冊

**用戶故事：** 作為管理員，我想要創建和管理手冊記錄，並控制手冊是否對外開放，以便我可以組織不同的技術文檔集合並管理其可見性。

#### 驗收標準

1. 當管理員訪問手冊管理界面時，系統應顯示所有現有手冊的列表及其基本信息和發布狀態
2. 當管理員點擊創建按鈕時，系統應顯示一個表單，用於創建新手冊，包括 url_slug、名稱（可翻譯）、描述（可翻譯）和 is_public 字段
3. 當管理員提交有效的手冊創建表單時，系統應創建手冊記錄並重定向到手冊詳情頁面
4. 當管理員嘗試創建具有重複 url_slug 的手冊時，系統應拒絕提交並顯示錯誤消息
5. 當管理員編輯現有手冊時，系統應允許修改名稱、描述、url_slug 和 is_public 字段
6. 當管理員刪除手冊時，系統應刪除手冊及所有相關的菜單項、頁面信息和頁面內容記錄
7. 當管理員查看手冊詳情頁面時，系統應顯示手冊的基本信息、發布狀態並提供導航以管理其菜單和頁面
8. 當 is_public 為 true 時，手冊應該對外部用戶可見
9. 當 is_public 為 false 時，手冊應該只對管理員可見

### 需求 2：管理階層式菜單結構

**用戶故事：** 作為管理員，我想要為每個手冊創建和組織階層式菜單結構，以便用戶可以在邏輯樹狀結構中導航文檔。

#### 驗收標準

1. 當管理員查看手冊的菜單管理界面時，系統應顯示完整的菜單樹及所有層級
2. 當管理員創建根菜單項時，系統應將其添加到手冊菜單結構的頂層
3. 當管理員在現有菜單項下創建子菜單項時，系統應將其作為子項添加到樹狀結構中並相應更新 ClosureTable
4. 當管理員將菜單項移動到不同的父項時，系統應更新樹狀結構並維護所有後代關係
5. 當管理員刪除菜單項時，系統應將其從樹中移除並根據配置的行為處理後代項（刪除或提升）
6. 當管理員編輯菜單項時，系統應允許修改名稱（可翻譯）、click_action、url 和 manual_page_info_id 字段
7. 當管理員查看菜單樹時，系統應顯示階層式結構，並通過視覺縮進顯示父子關係
8. 當菜單項的 click_action 為 "external" 時，系統應要求填充 url 字段並清空 manual_page_info_id
9. 當菜單項的 click_action 為 "page" 時，系統應要求指定 manual_page_info_id 並清空 url 字段
10. 當菜單項的 click_action 為 "expand" 時，系統應允許 url 和 manual_page_info_id 字段都為空

### 需求 3：管理頁面信息和元數據

**用戶故事：** 作為管理員，我想要創建和管理具有標題和關鍵詞的頁面信息記錄，以便我可以為每個手冊組織頁面元數據。

#### 驗收標準

1. 當管理員創建頁面信息記錄時，系統應將其與特定手冊關聯
2. 當管理員創建頁面信息記錄時，系統應允許輸入標題（可翻譯）和關鍵詞（可翻譯）字段
3. 當管理員編輯頁面信息記錄時，系統應允許修改所有支持語言中的標題和關鍵詞字段
4. 當管理員刪除頁面信息記錄時，系統應刪除所有相關的頁面內容記錄（所有語言）
5. 當管理員查看手冊的頁面信息列表時，系統應顯示所有頁面信息記錄及其標題和相關內容語言

### 需求 4：管理國際化頁面內容

**用戶故事：** 作為管理員，我想要以多種語言管理頁面內容，並支持富文本編輯和圖片插入，以便手冊可以被用戶以其首選語言訪問，並包含豐富的多媒體內容。

#### 驗收標準

1. 當管理員創建頁面內容時，系統應將其與特定的頁面信息記錄和語言代碼關聯
2. 當管理員創建頁面內容時，系統應提供 CKEditor 富文本編輯器用於輸入內容
3. 當管理員在富文本編輯器中編輯內容時，系統應提供文件管理器以插入圖片
4. 當管理員通過文件管理器插入圖片時，系統應保存圖片路徑為相對路徑或 CDN URL，不應寫死絕對路徑
5. 當管理員編輯頁面內容時，系統應允許修改特定語言的內容
6. 當管理員查看頁面信息記錄時，系統應顯示所有可用的內容語言版本
7. 當管理員嘗試為同一頁面創建重複的語言內容時，系統應拒絕提交並顯示錯誤消息
8. 當管理員刪除特定語言的頁面內容時，系統應僅移除該語言版本，同時保留其他語言版本
9. 當管理員查看頁面內容列表時，系統應按語言分組顯示內容，並指示哪些語言有內容

### 需求 5：驗證數據完整性

**用戶故事：** 作為系統管理員，我想要確保所有手冊記錄的數據完整性，以便系統保持一致性並防止無效狀態。

#### 驗收標準

1. 當創建手冊記錄時，系統應驗證 url_slug 在所有手冊中是唯一的
2. 當創建手冊記錄時，系統應驗證 url_slug 僅包含字母數字字符、連字符和下劃線
3. 當創建菜單項時，系統應驗證可翻譯的 name 字段在至少一種語言中不為空
4. 當創建 click_action 為 "external" 的菜單項時，系統應驗證 url 字段不為空且 manual_page_info_id 為空
5. 當創建 click_action 為 "page" 的菜單項時，系統應驗證 manual_page_info_id 不為空且 url 為空
6. 當創建 click_action 為 "expand" 的菜單項時，系統應驗證 url 和 manual_page_info_id 都為空
7. 當創建頁面信息記錄時，系統應驗證可翻譯的 title 字段在至少一種語言中不為空
8. 當創建頁面內容時，系統應驗證內容不為空
9. 當為頁面內容指定語言代碼時，系統應驗證其符合支持的語言格式（例如："en"、"zh-TW"）

### 需求 6：支持多語言數據輸入

**用戶故事：** 作為管理員，我想要高效地以多種語言管理內容，以便我可以為不同語言的受眾創建和維護手冊。

#### 驗收標準

1. 當管理員創建或編輯具有可翻譯字段的記錄時，系統應根據 config/manual.php 中的 supported_languages 顯示所有支持語言的輸入字段
2. 當管理員在可翻譯字段中輸入數據時，系統應使用 spatie/laravel-translatable 套件將數據存儲為 JSON 格式
3. 當管理員查看具有可翻譯字段的記錄時，系統應以清晰、有組織的方式顯示內容，顯示所有語言版本
4. 當管理員留下語言字段為空時，系統應允許提交（如果至少一種 required_languages 中的語言有內容）
5. 當管理員查看頁面內容時，系統應顯示語言選擇器以在可用語言版本之間切換
6. 當管理員創建或編輯記錄時，系統應在表單中標記 required_languages 中的語言為必填

### 需求 7：管理系統語言配置

**用戶故事：** 作為系統管理員，我想要通過配置文件管理支持的語言和必填語言，以便系統能夠根據業務需求靈活調整多語言支持。

#### 驗收標準

1. 當系統啟動時，系統應從 config/manual.php 讀取 supported_languages 配置
2. 當系統啟動時，系統應從 config/manual.php 讀取 required_languages 配置
3. 當管理員創建或編輯記錄時，系統應根據 supported_languages 生成相應的語言輸入字段
4. 當管理員創建或編輯記錄時，系統應根據 required_languages 標記必填語言字段
5. 當管理員嘗試提交記錄時，系統應驗證所有 required_languages 中的語言都有內容

### 需求 8：提供用戶友好的管理界面

**用戶故事：** 作為管理員，我想要一個直觀的界面來管理手冊，以便我可以高效地執行 CRUD 操作並在相關記錄之間導航。

#### 驗收標準

1. 當管理員訪問手冊管理部分時，系統應顯示一個儀表板，提供對所有管理功能的快速訪問
2. 當管理員查看手冊詳情頁面時，系統應提供導航選項卡或按鈕以訪問菜單管理、頁面信息和頁面內容
3. 當管理員執行操作時，系統應顯示適當的成功或錯誤消息
4. 當管理員刪除記錄時，系統應在進行前顯示確認對話框
5. 當管理員查看記錄列表時，系統應提供分頁、排序和篩選選項
6. 當管理員創建或編輯記錄時，系統應提供清晰的字段標籤和驗證錯誤消息
7. 當管理員在相關記錄之間導航時，系統應保持上下文並提供麵包屑導航
