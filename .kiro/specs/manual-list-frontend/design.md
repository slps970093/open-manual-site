# 設計文件：手冊列表前端

## 概述

手冊列表前端是一個響應式 Web 介面，用於展示和發現技術文檔手冊。該設計基於現有的 Bootstrap 5 模板，提供了一個直觀的用戶介面，支持搜尋、語言篩選和響應式佈局。該功能與現有的 Laravel 後端集成，使用 Spatie Translatable 進行多語言支持。

## 架構

### 技術棧

- **前端框架**: Laravel Blade 模板引擎
- **CSS 框架**: Bootstrap 5
- **JavaScript**: Vanilla JavaScript（無框架依賴）
- **後端集成**: Laravel 路由和控制器
- **多語言**: Spatie Translatable（已在 Manual 模型中實現）
- **資料庫**: Manual 模型

### 頁面流程

```
用戶訪問 /manuals
    ↓
FrontendController 加載手冊列表頁
    ↓
檢索所有公開手冊（按語言篩選）
    ↓
渲染手冊卡片網格
    ↓
用戶可以：
  - 搜尋手冊
  - 更改語言
  - 點擊卡片查看詳情
```

### 組件架構


## 組件和介面

### 1. 手冊卡片組件

**責任**: 顯示單個手冊的信息

**輸入**:
- `manual`: Manual 模型實例
- `language`: 當前選擇的語言代碼

**輸出**:
- 渲染的 HTML 卡片，包含：
  - 手冊圖標/表情符號
  - 本地化的標題
  - 本地化的描述
  - 建立日期（格式化）
  - 最後更新日期（格式化）
  - 指向手冊詳情頁的鏈接

**樣式**:
- Bootstrap card 類
- 懸停效果（陰影增強）
- 響應式寬度（3 列/2 列/1 列）

### 2. 搜尋篩選組件

**責任**: 提供即時搜尋功能

**功能**:
- 監聽輸入事件
- 執行不區分大小寫的文本匹配
- 篩選手冊卡片
- 更新 URL 查詢參數
- 顯示/隱藏空狀態

**實現**:
- 使用 JavaScript 事件監聽器
- 客戶端篩選（無需伺服器往返）
- 防抖搜尋輸入以提高性能

### 3. 語言選擇器組件

**責任**: 允許用戶選擇語言

**功能**:
- 顯示可用語言列表
- 持久化選擇到 localStorage
- 重新加載頁面或動態更新內容
- 篩選手冊以顯示所選語言

**實現**:
- HTML select 元素
- JavaScript 事件監聽器
- localStorage API 用於持久化

### 4. 空狀態組件

**責任**: 在沒有結果時提供反饋

**場景**:
- 搜尋無結果
- 所選語言無手冊
- 資料庫中無公開手冊

**訊息**:
- 清晰的說明文本
- 建議的後續步驟
- 可選的圖標或插圖

## 正確性屬性

一個屬性是應該在系統的所有有效執行中保持真實的特徵或行為——本質上是關於系統應該做什麼的正式陳述。屬性充當人類可讀規範和機器可驗證正確性保證之間的橋樑。

### 屬性 1：搜尋篩選準確性

*對於任何* 手冊列表和搜尋查詢，搜尋結果應該只包含標題或描述中包含搜尋文本的手冊（不區分大小寫）。

**驗證: 需求 3.1, 3.2**

### 屬性 2：語言篩選一致性

*對於任何* 手冊和選擇的語言，如果手冊在該語言中有翻譯，它應該以該語言顯示；如果沒有翻譯，它應該被隱藏或顯示備用語言。

**驗證: 需求 4.1, 4.2**

### 屬性 3：響應式佈局適應性

*對於任何* 視口寬度，頁面應該根據以下規則調整列數：
- ≥1024px: 3 列
- 768px-1023px: 2 列
- <768px: 1 列

**驗證: 需求 5.1, 5.2, 5.3**

### 屬性 4：公開手冊可見性

*對於任何* 手冊列表，只有標記為 `is_public = true` 的手冊應該在頁面上顯示。

**驗證: 需求 1.4**

### 屬性 5：日期格式化一致性

*對於任何* 手冊的建立日期和更新日期，它們應該以人類可讀的格式顯示，並使用用戶的區域設定。

**驗證: 需求 7.1, 7.2, 7.3**

### 屬性 6：語言選擇持久化

*對於任何* 用戶選擇的語言，在頁面重新加載後，應該恢復相同的語言選擇。

**驗證: 需求 4.4, 4.5**

### 屬性 7：搜尋 URL 參數同步

*對於任何* 活動搜尋查詢，頁面 URL 應該包含搜尋查詢參數，以便用戶可以書籤保存搜尋結果。

**驗證: 需求 3.5**

### 屬性 8：手冊卡片完整性

*對於任何* 顯示的手冊卡片，它應該包含圖標、標題、描述和日期元數據。

**驗證: 需求 2.1, 2.2, 2.3, 2.4**

### 屬性 9：搜尋清除恢復

*對於任何* 活動搜尋查詢，清除搜尋輸入應該恢復所有手冊的顯示（尊重語言篩選）。

**驗證: 需求 3.4**

### 屬性 10：語義 HTML 結構

*對於任何* 渲染的頁面，它應該包含語義 HTML 元素（header、nav、main、section、article）和適當的標題層級（h1、h2、h3）。

**驗證: 需求 9.2, 9.3**

### 屬性 11：無障礙屬性

*對於任何* 表單輸入和圖像，它們應該包含關聯的標籤、ARIA 屬性或 alt 文本。

**驗證: 需求 9.4, 9.7**

### 屬性 12：SEO 元標籤

*對於任何* 頁面渲染，它應該包含適當的元標籤（title、description、keywords）。

**驗證: 需求 9.1**

### 屬性 13：手冊卡片導航

*對於任何* 手冊卡片，點擊它應該導航到包含手冊 URL slug 的詳情頁。

**驗證: 需求 6.1, 6.2**

## 錯誤處理

### 資料庫查詢失敗

**場景**: 檢索手冊時資料庫連接失敗

**處理**:
- 捕獲異常
- 顯示用戶友好的錯誤訊息
- 記錄錯誤以供調試
- 提供重試選項

### 缺少翻譯

**場景**: 手冊在所選語言中沒有翻譯

**處理**:
- 顯示備用語言版本
- 或從顯示中隱藏手冊
- 在空狀態中建議替代語言

### 無效的 URL 參數

**場景**: 用戶提供無效的搜尋查詢或語言代碼

**處理**:
- 驗證輸入參數
- 使用預設值（例如：預設語言）
- 清理搜尋查詢以防止 XSS

## 實現注意事項

### 性能優化

1. **資料庫查詢**:
   - 使用 eager loading 避免 N+1 查詢
   - 只檢索必要的欄位
   - 考慮分頁以處理大量手冊

2. **客戶端篩選**:
   - 使用防抖搜尋輸入
   - 避免不必要的 DOM 操作
   - 考慮虛擬化大型列表

3. **資源加載**:
   - 最小化 CSS 和 JavaScript
   - 使用 CDN 提供靜態資源
   - 考慮延遲加載圖像
